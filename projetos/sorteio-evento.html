Sorteio de evento

Sistema de inscrições e sorteios para eventos presenciais, com cadastro via QR Code e sorteios ao vivo em um painel protegido.

Tecnologias
  • Python
  • Flask
  • PostgreSQL
Ano
2026

O que o sistema precisava resolver

  • Agilizar o cadastro dos participantes pelo celular, sem instalar nada.
  • Permitir que cada pessoa se inscrevesse apenas uma vez.
  • Garantir um sorteio justo e transparente para todos.
  • E impedir que um participante fosse sorteado mais de uma vez.

Do QR Code ao vencedor

O caminho de um participante, em três telas.

O QR Code vai para o telão

Gerado a partir do endereço do formulário.

O participante se cadastra

Tudo numa tela só; na confirmação, o código com que concorre.

A organização sorteia

Um clique por categoria, e o vencedor aparece com os dados para contato.

Decisões técnicas

O que faz o sorteio ser justo e o cadastro, rápido.

  • Sorteio

    Ninguém é sorteado duas vezes

    Dois cliques ao mesmo tempo nunca levam a mesma pessoa.

    O banco escolhe ao acaso entre quem ainda não foi sorteado, com FOR UPDATE SKIP LOCKED.

  • Cadastro

    Uma inscrição por pessoa

    A mesma pessoa não consegue se inscrever duas vezes.

    O CPF é conferido pelos dígitos verificadores, no navegador e no servidor, e CPF e registro profissional são únicos no banco.

  • Privacidade

    Cuidado com os dados pessoais

    Ninguém se inscreve sem consentir, e o painel é protegido.

    O consentimento é obrigatório, o painel exige sessão com cookie só em HTTPS e todos os formulários têm proteção contra CSRF.

Ver mais 4 decisões
  • Acesso

    Limite de tentativas só onde faz sentido

    O login é protegido, e o formulário aguenta o evento inteiro no mesmo Wi-Fi.

    O login do painel aceita dez tentativas a cada quinze minutos por IP. O formulário público não tem limite, de propósito: no evento, todos chegam pelo mesmo Wi-Fi e, portanto, pelo mesmo endereço.

  • Exportação

    Planilha que abre pronta

    A lista de inscritos sai em Excel, pronta para usar.

    Cabeçalho fixo, filtros por coluna e os sorteados em destaque. Texto que começa com = é gravado como texto, para nunca virar fórmula.

  • Configuração

    Um evento novo sem mexer no código

    Para outro evento, basta trocar as variáveis de ambiente.

    O nome do evento, as categorias e o aviso de quando acontece o sorteio vêm de variáveis de ambiente. Com uma categoria só, ela já vem selecionada no formulário.

  • Testes

    Testes que rodam em qualquer máquina

    Dá para testar sem o banco de produção.

    Os 28 testes usam SQLite em memória e variáveis fictícias, sem precisar do PostgreSQL de produção.
